# 从成员确认到内测、审核、发布

> 2026-10-15 最新进度：用户已确认是开发者、已提供 AppID、有 Mac；测试云尚未开通，审核具体事项未核实。以下为通用办理说明，当前执行状态见 [最新交接](../HANDOFF.md) 与 [内测指南](18-beta.md)。费用与平台能力以实际账号和官方订单为准。

## 当前状态修订

用户最新说明：“添加成员后的确认”正在等待；微信认证显示“未认证”。这不等于代码审核。此前提到的注册主体核验是否已经通过，仍需实际后台确认，不能仅凭可以加成员就推断全部主体手续完成。

## 1. 完成项目成员权限

管理员与开发者查看后台/微信的确认提示，按指定人员完成。后台成员列表出现开发者微信及正确角色，再由开发者实际登录确认。首版建议开发者+运营者，角色细项以当前界面为准；后续版本提审发布需有对应权限。只加体验者不能开发上传。

同一个微信管理自己的公众号，不妨碍作为公司小程序项目成员，不用解绑原公众号。不更换公司管理员或主体；不使用自己公众号的 AppID 代替公司小程序 AppID。

## 2. 基本资料和 AppID

登录公众平台核对公司小程序：名称、头像、介绍、客服、主体状态与小程序 AppID。最终名称和品牌授权如平台要求由主理人补。AppID 可进入非秘密配置；AppSecret、上传私钥和云凭据不可进前端或仓库。原生云函数微信身份无需为了“登录”盲目在前端填写 AppSecret。

## 3. 微信认证与备案并行准备

官方认证指引说明，企业小程序认证成功不是普遍的提交发布审核前提，特定能力另有要求；不要宣称所有企业不认证都不能上传。对本项目长期运营与云端接入，建议管理员现在启动认证，开发继续并行。开通云服务、手机号等能力时逐项核对条件，不因不支付就认定所有认证要求消失。

认证入口：设置→基本信息→微信认证→详情；企业按页面填写最新营业执照、联系人及相应资料，核对发票、授权和对公验证要求后，在官方订单支付。先预留约300元，实际费用看订单；并非购买云资源。审核人员可能联系预留联系人，按订单期限补件。认证与年审、主体真实性、小程序备案、代码审核是不同事项。

备案：通过微信后台备案入口，按现行要求填主办者、服务负责人、联系方式与服务信息；开发者整理技术项，主理人处理本人/短信核验。需补行业前置材料则真实补齐。备案办理本身不收费，第三方代办不是政府强制收费。小程序备案与另有网站时的域名备案也不是一回事。

## 4. 本地开发与上传准备

原生项目准备正确 project.config.json、app.json、编译产物、基础库/隐私接口。开发者用自己的微信登录官方开发者工具调试；Linux 使用官方 miniprogram-ci。

管理员在“管理→开发管理→开发设置→小程序代码上传”按实际界面生成上传私钥；按真实公网出口设置白名单。首版不关闭白名单凑成功。私钥存代码目录外，实际路径写 config/local.json，不要生成并打包给第三方。

本包 CI 脚本要求 future app/miniprogram 下有真实可运行产物；构建生成 build-meta.json，字段 appId、envId、target、version，必须与本地配置一致。元数据用于辅助核对，不能替代检查源码实际初始化的 EnvId。

    node scripts/wechat-ci.cjs preview --env test --config config/local.json
    node scripts/wechat-ci.cjs preview --env test --config config/local.json --execute
    node scripts/wechat-ci.cjs upload --env test --config config/local.json --execute

第一条只预检，不读私钥正文、不联系微信。后两条会实际使用密钥预览或上传；在产品实现、真实配置、安装 CI 依赖之后执行，当前交接包直接运行会提示缺项。测试上传不会自动变成体验版。

TypeScript 需要由实际构建流程输出微信可运行 JS；原生 WXML/WXSS 和必要 JSON 都应存在。用了 npm 时需按官方工具/CI当前能力构建 npm 产物，不能仅拷贝 package.json。脚本不会自动替开发者实现前端构建。

## 5. 内测

开发版：有对应权限的开发者调试。体验版：在公众平台版本管理选定上传的开发版本为体验版，添加体验成员，分享体验码给这些成员。公开版：审核通过并发布后公众可用。三种不是同一状态。

虚构数据可先测页面；真实报名、身份和积分需测试云环境。体验成员权限不等于员工角色。测试用户还要通过业务初始化绑定领队/运营权限，不能把腾讯平台角色当后端权限来源。

内测至少验证新用户零分、最后一个名额竞争、取消、候补、出发结束核验、重试不重复发分、榜单退出，以及员工越权失败。

## 6. 提审前准备

备案及适用条件完成；真实类目和行业材料；隐私保护指引与实际接口一致；真实活动内容、组织者和客服；全流程可用，不是空壳或只有“敬请期待”。本项目无支付，但真实线下收费、训练和多日活动如实说明。

管理员权限工作台是功能的一部分，不藏起来规避审查。按平台测试说明提供审核可用的角色/路径，不能公开静态管理员密码或通过前端万能口令提权。确需审核专用权限则受限、隔离、可追溯，不赋予真实名单和财务等敏感访问。

## 7. 审核包与公开发布

先部署向后兼容的正式后端，确认数据库/索引/权限/备份；构建绑定正式 EnvId 的前端；手机预验收；上传 production 版本；在版本管理提交代码审核、填写类目/说明/所需资料。提审、备案、认证是独立流程；不承诺固定几天或包过。

若驳回：保存原文，判断是功能/隐私/类目/资质/内容，真实修复，再提交；不得只换词隐藏经营内容。通过后由有权运营者操作发布，首版先小范围实际运营观察。正式发布时记录代码、函数、数据迁移和规则版本。

## 8. 自动化边界

miniprogram-ci 解决预览/上传等官方开放能力，不等于平台任何页面都能自动操作。miniprogram-mp-ci 当前文档面向批量成员管理，管理员确认后生效，不是通用发布/备案 API。首版提审发布在公众平台完成。若后续引入其他官方发布接口，另核对权限、账号条件和密钥范围。
