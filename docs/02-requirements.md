# 产品范围与需求

## 目标

帮助一个机车俱乐部统一招募、报名资格、参加记录和积分。用户不靠付钱买积分获得高难度资格。成长记录、人工技能评估与每场核验共同决定是否可参加。

## 确认的第一版范围

微信建立用户身份；活动列表详情；积分和技能准入；报名意向；审核/候补；员工线下联系后确认参加；出发和结束核验；活动完成结算；个人积分流水；参加次数与自愿公开榜单；年度奖励名单管理；员工工作台。

实际活动是线下收费的非铺装摩托车越野、训练及多日穿越，不搞比赛。食宿交通参加者自理。小程序不标价、不支付、不存金额、支付状态、退款金额或订单号；“确认参加”仅表示资格与线下安排确认，不是支付成功。线下服务条款及必要费用说明由公司真实告知。

## 用户故事与验收出口

| 用户 | 要做的事 | 可观察结果 |
|---|---|---|
| 新车友 | 先看活动再决定建立身份 | 游客可读公开活动；报名时按必要流程授权 |
| 新车友 | 从低门槛活动开始积累 | 零积分至少有合适入门活动；不能领取演示老会员积分 |
| 老车友 | 判断自己能否报名 | 显示积分/资格差距、截止时间、名额及规则 |
| 申请人 | 查看进展并取消 | 清楚区分待审核、候补、待确认、已确认，取消后不再可签到 |
| 参加者 | 出发与结束核验 | 现场核验后产生本人记录，不等同于领积分 |
| 参加者 | 查看成长和年度记录 | 分数和流水可核对；成长分用于门槛，年度分用于当年奖励 |
| 自愿上榜者 | 展示经历 | 公开昵称、次数、积分；退出后榜单与缓存生效 |
| 运营 | 发布和管理活动 | 可看本人权限范围名单、资格、候补、确认和通知情况 |
| 领队 | 核验人员与结束情况 | 只能管理自己负责场次，不可改分或随意扩权限 |
| 主理人 | 纠错和年终结算 | 有原因、前后值、审计和可追溯奖励名单版本 |

## 不在第一版

线上价格与支付、缴费台账、储值/会费、商城与积分兑换、旅游代订、比赛计时、第三方俱乐部入驻、公众发帖评论私聊、公开精确线路、持续 GPS 轨迹。未来新增都重新设计、核对类目、隐私和成本。

## 产品原则

不以积分替代技能和安全；不把报名等同参加；不把签到等同完成；不把演示数据导入真实会员。活动更改和规则调整必须可追溯，不能事后偷偷改规则使积分失真。

## 推荐首期上线人群

先按成年人设计，作为 proposed 规则待主理人确认。若要服务未成年人，需另处理监护、培训条件、隐私及适用平台规则，不能仅修改年龄数字。一般浏览不收身份证和健康资料；报名按真实必要性最少收集。

## 2026-10-15用户补充：已确认，待后续版本实现

当前只有一个俱乐部，200人以内，约每月一场或更频繁。优先解决组织与记录缺失、负责人手工统计积分的问题。成员包括几位创始／核心成员和普通／新成员。

创始／核心成员满足资格、规则与名额条件时直接确认参加，不经过收款确认路径；普通成员申请后收到线下缴费提示，由管理员核对后确认参加。不新增线上支付、金额或缴退款台账。客户要求核心成员即使积分较低，也能在默认成员展示中靠前。

当前0.1尚未实现这些身份分流。推荐展示与真实积分分开、具体界面和工作单见 [长期产品设计](20-product-design.md)，其中设计建议不等于已获主理人逐项批准。
