# 页面与员工后台

## 车友端

| 页面 | 内容 | 操作与失败反馈 |
|---|---|---|
| 活动列表 | 封面、名称、日期、天数、难度、门槛、招募状态 | 分页、状态筛选；加载/空/失败；不公开精确敏感线路 |
| 活动详情 | 真实内容、强度、必要技能装备、风险、截止、规则、食宿交通自理、组织者与客服 | 立即申请/查看申请；显示差距、截止和候补规则，不显示价格 |
| 身份建立 | 用户规则、必要个人信息、昵称；可选头像 | 微信身份在服务端生成；拒绝非必需权限仍可浏览 |
| 报名表 | 该场必要信息、资格状态、规则版本确认 | 防重复提交；说明“申请待确认”不等于保证参加 |
| 我的活动 | 每场状态、时间线、通知与核验结果 | 截止前按规则取消；已出发交工作人员处理 |
| 我的积分 | 成长总分、年度分、完成次数、分页流水、原因 | 年份选择，错误申诉入口，不能自行改分 |
| 榜单 | 成长/年度/参加次数维度与并列名次 | 公开开关、本人位置、退出结果 |
| 个人与隐私 | 基本资料、客服、隐私说明、授权管理、注销申请 | 注销后说明保留信息依据及处理进度 |

报名表不要为方便一次性收身份证正反面、驾驶证照片、完整健康史。需要资格时优先存审核结果、类别、有效期、审核人，敏感原件必要时另设计受限材料流程和删除期限。

## 员工工作台，首版在同一小程序实现

隐藏入口只改善界面，不承担权限保护。服务端返回当前角色；普通成员直接调用员工接口必须拒绝。平台开发者/运营者身份不自动是俱乐部 owner。

| 页面 | 操作 | 限制 |
|---|---|---|
| 工作台首页 | 本场待办、审核数、出发/结束人数、异常 | 按 clubId 和活动授权过滤 |
| 活动编辑 | 草稿、封面、规则、时间名额、发布预检 | 发布后重要字段更改生成版本，关键规则冻结 |
| 报名名单 | 按状态筛选、资格审核、候补、确认/取消、联系状态 | 无缴费开关；必要联系电话仅有权人员可见 |
| 现场核验 | 核对昵称/必要身份、出发和结束、退出原因 | 领队/签到员限本场；撤销需理由和审计 |
| 结算预览 | 逐人结果、冻结分值、异常清单、提交与重试 | 未核验不可正常完成；无直接编辑总分 |
| 积分更正 | 查原流水、提交理由、冲正及复核 | 首版主理人权限；页面显示影响而非随意输入余额 |
| 年度奖励 | 生成年份快照、查看版本、确认发放 | 记录实际奖品/状态，不形成线上兑换或现金余额 |
| 角色与审计 | 绑定员工、活动分配、查看重要日志 | 主理人授权；不能通过客户端自升角色 |

## 界面交付标准

中文状态使用 contracts/states.json 对应文案；返回失败必须区分名额、资格、截止、权限和网络。重要提交给出确认内容，成功显示服务端真实结果。避免透出 OpenID、EnvId、接口堆栈等给普通用户；这些只进入脱敏技术日志。

员工还需一页操作说明：发布、处理报名、出发清点、结束清点、发分、纠错。不能以腾讯云控制台改数据库作为日常后台。
