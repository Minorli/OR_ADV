## Linux 构建，Mac 导入，手机扫码

Linux：

```sh
npm ci
npm ci --prefix cloudfunctions/oradv --ignore-scripts
cp config/local.example.json config/local.json
# 填写本项目 AppID，未知 EnvId 保持空白；不要覆盖已有 local.json。
npm run build
npm run pack:preview
```

如果已有 `config/local.json`，保留并编辑原文件。构建默认 `mock/test`；不会登录腾讯、创建环境、购买套餐或上传微信代码。生成的 `project.config.json`、`runtime-config.json`、JS 文件均不提交 Git。

Mac 两种用法：

1. 开发者工具预览包：将 `dist/OR_ADV-mock-preview.zip` 复制到 Mac，解压，导入其中 `OR_ADV-preview/`。导入时核对 AppID，再点击工具栏“预览”，用项目开发者本人微信扫码。
2. 持续开发：在 Mac 克隆同一仓库，安装依赖、填写本地配置、构建后导入 `app/miniprogram/`；也可把 Linux 构建后的整个 `app/miniprogram/` 同步到 Mac 的独立目录。保持目录完整，并保留 Mac 自己的工具私有设置。

手机适合体验页面和操作流程；开发者工具负责导入、预览和定位问题。预览不等于已发布，普通成员长期试用需要后台体验成员权限及体验版本。工具安装与角色权限以 [微信官方开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)、[发布流程](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html) 为准。

## 0.2a模拟模式体验顺序

1. 游客查看入门活动和公开联系说明，在“我的”或报名页同意后建立演示身份。
2. 在“我的”切换普通车友，先从“同行”打开已确认的林道活动，看行前清单与已有历史，再从“我的”查看积分。到入门体验提交新申请，检查“待管理员确认”和线下缴费说明；演练不实际缴费。候补、资格未通过不会提示立即缴费。
3. 在“我的”切换演示主理人，进入员工工作台，选择本场。通过昵称或完整数字成员编号查找申请，核对后确认参加。
4. 同一工作台可以修改已有行前安排、负责人和准备清单；这是受限资料，不能放进公开介绍。切回成员，从“同行”进入本场资料，核对清单和本人进展。
5. 单独切换“创始成员”，申请仍开放且有名额的适用场次，检查直接确认路径；创始身份没有员工权限或报名赠分。
6. 主理人从“成员与身份管理”认定／撤销身份、授权员工、核对技能及配置公开联系；用本人卡片的编号通过已有可信渠道核对，避免重名误认。
7. 在“俱乐部”查看默认推荐；成员须在“我的”分别同意推荐与积分榜公开。推荐优先创始成员，积分榜按实际记录，退出推荐不取消身份。
8. 员工默认先看今日场次的待回场人员，也可选“林道基础复训”直接预览并执行待结算名单，重试一次，核对正常完成只增加一笔奖励。切回原成员查带活动名称的流水。需要完整新场次流程时，在入门活动依次开始、出发／结束核验并结算。

本轮使用独立v3数据、身份和准备清单，保留旧版演练存储。首次进入或点击“重置本机演示数据”时按当天生成日期，随后保留本机修改；隔天要重演今日核验时可重置。重置只恢复本机虚构数据与演示清单，不清理真实清单，不导入云数据。不同手机之间不共享模拟记录。

编号版会自动为旧v3档案补数字编号，无需重置：演示主理人为0，其他成员使用正数。旧头像、申请、积分及勾选清单保留；保存失败会明确提示，原档案不被清空。切换演示主理人可检查0号显示与复制，再到成员目录或现场名单按完整编号查找，0不会匹配10或20。

新导航为“首页／排行／历史／我的”。首页默认展示招募；“历史”可在未登录时查看已结算活动，并按月份或活动／区域查找。本人申请与行前资料从“我的 → 我的同行”进入，积分流水在“我的”中。公开与受限资料分开，活动取消或申请取消后，后续读取受限资料会被拒绝；历史申请仍保留。

## 开通测试云：一次性由有权人员办理

按 [CloudBase 官方创建环境指引](https://docs.cloudbase.net/quick-start/create-env)（2026-10-16 查阅）：

1. 在 Mac 微信开发者工具中登录开发者本人的微信，打开**公司小程序**项目，核对 AppID。
2. 点击顶部“云开发”。先检查有没有已有环境；首次开通按页面完成服务开通与必要授权。
3. 为本项目建立测试环境，例如名称 `oradv-test`；确认账户归属、实际套餐、到期、数据库能力和费用。若出现付费订单，由有权付款人确认，开发脚本不会代购。
4. 从环境设置复制实际 **EnvId**。名称 `oradv-test` 不能替代 EnvId。只需提供 EnvId、地域和到期信息，不要发登录会话或密钥。
5. 若提示主体、认证、绑定或授权不足，记录平台原文，交管理员完成对应步骤；继续本地开发。

优先从小程序工具创建关联环境；已有腾讯云环境需按官方指引核对绑定关系。开发者成员权限、云资源权限、产品内员工权限分别核验。

## 接入真实测试版

拿到测试 EnvId 后，依 [云环境部署](10-cloud.md) 核对集合、索引、安全规则与函数配置，先预检再对测试环境执行。敏感集合不开放客户端直读写，所有业务通过云函数。

```sh
# config/local.json 中设置真实 AppID 和 environments.test.envId
npm run build:cloud
node scripts/wechat-ci.cjs preview --env test --config config/local.json
```

构建只生成产物；上传预检只核对配置，不代表云端可用。缺少上传私钥时，用 Mac 官方工具预览即可。Linux 自动预览还需管理员生成上传私钥、设置公网出口白名单；私钥放仓库之外，路径写入本地配置。

真实云端需部署者初始化俱乐部和首位 owner，之后由 owner 授权运营及限场领队。首次注册用户不自动成为管理员。先跑一条“零积分新用户→申请→审核确认→出发结束→结算→本人流水”链路，再邀请其他体验成员。

真实测试必须记录微信身份、权限拒绝、末席并发、重复结算、退出榜单，以及 iOS/Android 结果。尚无证据的项目继续标待执行；[完整验收清单](12-acceptance.md) 不因本地自动化通过就全部打勾。

## 微信登录后设置昵称和头像

正式云版的入口为“我的 → 同意并用微信登录”。系统按本次微信身份建立或恢复同一份成员档案；首次真实注册是普通成员、零积分。浏览活动不必登录，创始成员及员工身份仍由主理人另行核定。

登录后进入“昵称与个人资料”，可手填昵称，也可通过微信昵称输入能力快速填写；点击头像主动选择图片后保存。昵称和头像都不是登录的必填项，不自动获取手机号；骑手档案中的联系方式由本人主动填写并确认用途。头像本期只在本人资料页显示，公开推荐和积分榜仍单独征求昵称与积分展示同意。

头像保存前会压缩和检查，传输为最多64KiB的JPEG/PNG。正式环境由鉴权云函数保存到私有云存储；本机演示只写本机自有文件。演示角色切换不等于真实微信登录，重置会清理本轮演示头像。关闭重开应恢复本人保存的资料，图片加载失败可单独重试。

测试EnvId、管理员CLI授权、v3数据库及存储拒绝规则、测试函数部署均已完成；云版已上传开发版本。接下来按 [部署说明](10-cloud.md#微信登录与个人头像接入) 用两个独立微信账号验证身份、头像和私有材料隔离。无需为本项目登录提供AppSecret，也不要把密钥发到聊天。

能力依据：[CloudBase原生微信调用](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)、[微信官方头像昵称组件说明](https://github.com/wechat-miniprogram/mp-user-avatar/blob/master/README.md)。此处直接使用原生按钮和输入框，不安装已归档的组件包；最低基础库、昵称审核回调与手机行为需要实际开发者工具和iOS／Android核验。

## 本轮内测限制

- 活动发布后冻结关键字段；本轮不提供发布后改期及重新征求同意的完整工作流。
- 已有成员身份、员工授权和技能核验管理；完整审计查询与年度奖励管理页面仍待后续。
- 隐私模板、内容安全接入、备份恢复和真实手机验收仍需结合实际环境完成；模拟通过不等于正式上线验收完成。

## 构建与预览一致性

监听模式方便日常开发，不生成可上传的最终元数据。停止监听后，先执行一次 `npm run build` 再预览或打包。成功构建的元数据绑定所有实际部署文件的SHA256；构建失败、文件变动、项目内出现秘密文件名或符号链接时，预览和打包会拒绝继续。Mac工具生成的 `project.private.config.json` 被排除。

## 多页面请求字段报错修复
