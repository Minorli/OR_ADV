# 员工操作手册

对应 `0.2.0-test.5`。员工使用同一小程序内的工作台；微信项目开发者、业务创始成员与员工是不同身份。当前预览使用虚构数据，演练时不实际缴费或联系示例对象。

## 1. 先配置身份与真实联系渠道

真实云用户先建立自己的微信身份，可信部署者一次性初始化首位主理人。之后主理人在“我的 → 成员与身份管理”办理日常成员和员工授权。

成员可提供本人卡片上的数字编号，方便通过既有可信渠道核对和查找同名成员。编号不是登录凭据，也不能代替实际核实。不要只按相同昵称授予创始身份。

主理人可以认定或撤销创始成员，填写依据；若实际制度需要，才设置期限。推荐顺序只能管理已由本人同意公开的展示，不能替成员开启公开同意。创始身份不增加积分或授予后台权限。

在公开联络设置填写经同意可公开的真实称呼、联系方式和说明。联系方式缺失时不能发布新活动或接受适用的新申请。示例信息只用于本机演示。

员工授权分别设置：主理人、运营、领队、现场核验员。领队和核验员必须指定场次；不要给现场角色授予全俱乐部范围。保存后核对实际角色及期限。系统阻止撤销自己的主理人权限或为自身设置到期锁死入口。

## 2. 发布一场活动与行前安排

创建草稿，填写公开内容、区域、日期、报名截止、人数、成长门槛、必要技能、装备、安全说明和积分规则。本轮每场最多30人；先确认主理人批准的规则，再发布。发布后关键规则冻结。

行前安排在独立编辑区填写集合地点／时间、本场负责人、联系办法、准备清单和须知。公开活动详情不包含这些受限字段；只有符合条件的已确认成员及授权员工可读。未填写时，成员看到“行前安排尚未发布”，不会被伪造资料填充。

新车友应有适用的入门活动。需要额外技能时，先由有权人员记录真实核验结论与有效期，不能以创始身份、积分或“审核通过”代替技能。

## 3. 两类报名与候补

- 创始成员满足本场资格、规则及名额条件时直接确认参加；首次申请、取消后重报、候补获席都重新核对。
- 普通成员获得适用名额后进入待管理员确认，看到线下缴费安排提示。运营实际核对资格及线下安排后点击“确认参加”；无需先单独点击审核通过再确认，旧审核操作仍兼容。
- 候补和资格待核验不直接提示立即缴费。候补不占名额，按顺序重新核验后提升，不静默挤掉已确认人员。
- 推荐展示靠前不等于插队、预留专席或获得后台权限。当前没有金额、订单、付款或退款台账。

名单支持昵称与完整数字编号查找、状态筛选。拒绝、取消、退出及纠错要填客观原因；冲突提示后先刷新，不能反复覆盖。

## 4. 当天核验与异常处理

开始活动后现场核对本人、装备和资格，逐人记录出发与返回。未确认、已取消者不可出发。名单优先显示未返回人员，创始与普通成员采用相同的清点顺序和安全要求。

每天分别清点；多日活动当天返回不等于整场完成。核验工作台显示当天出发／返回与未返回人数。打开某个筛选后，也要检查其他日期遗留的未处理记录。

未到、安全退出和正常完成分别处理。断网或超时不能当成功，刷新核对后再沿原流程重试。个人准备清单的勾选不是现场核验。

当前仅接受当日核验，跨日补录及自动离线写入没有开放。现场人工备用安排由组织方制定，未处理清楚的记录不能直接发分。

## 5. 自动积分与纠错

结束清点后结束活动，预览正常完成、异常和待处理人员，再提交结算。系统按本场冻结规则计算，负责人不逐人填写总分。逐人事务失败会留下清单，核查后重试不会重复发分。

创始成员确认报名不自动发分。成员积分流水现在关联活动名称，可回到本场记录。更正错误完成用主理人冲正，写原因并保留原流水，不直接改余额；完成历史标明“完成已更正”。

全俱乐部累计报表、历史积分迁入、年度快照超过30人的分批处理仍属后续0.2b，不把当前成员目录的200人验证等同这些功能已完成。

## 6. 内测报障

记录场次、时间、步骤、提示与traceId（如有）。真实名单、联系方式、OpenID、证件、凭据、台账和导出不要发公开GitHub。主理人未定的积分、占位与异常政策继续记入 [决策清单](15-decisions.md)，不把演示数值当承诺。
