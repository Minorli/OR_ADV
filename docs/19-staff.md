# 内测员工操作手册

业务员工使用小程序内的“员工工作台”。微信项目开发者、运营者与业务员工不是同一个身份；真实员工由主理人授权，领队和核验员只能管理获授权的场次。模拟版允许切换虚构身份以检查流程。

## 首场活动

1. 在工作台创建草稿，填写活动介绍、公开集合区域、时间、报名截止、人数（内测最多30人）、装备、安全提示、成长门槛和奖励规则。
2. 先确认主理人批准的资格与积分政策，再发布。发布后规则冻结；不要通过修改总分补救规则错误。
3. 新车友应有零门槛入门活动；不能用积分代替技能和安全评估。精确敏感线路不放公开页面。

## 报名与候补

按场次查看名单，区分待审核、候补、待联系确认和确认参加。审核通过后，还需联系并确认参加。确认参加表示资格与线下安排已核对，不是支付成功；系统没有缴费开关。

待审核和待确认暂按 proposed 规则占位，候补不占位。释放名额后由运营点击提升候补，按顺序检查最早5名候补，提升时再次核验资格；不可跳过审核直接标记参加。若候补资格失效，先联系并做有原因的审核处理；当前没有自动提升与自动订阅通知。收到“版本变化”提示时刷新并核对当前状态，不要反复点击覆盖。

## 现场核验

开始活动后，核对本人并记录出发；结束时逐人核验返回结果。未确认、已取消的申请不能出发核验。安全退出、未到与正常完成分别处理；无出发记录不能直接正常完成。

多日活动每天核对人员，整场只结算一次。不得用静态截图、口头“都到了”或直接改数据库代替核验。

## 结算与纠错

活动结束后先预览结算名单，检查未归队、异常和待处理人员，再执行结算。只报名或只签到不发完成分；重复执行不能重复发分。失败时按原场次重试并检查任务结果。

本人可在积分页看到流水，主理人通过追加冲正处理已结算错误，填写原因并关联原流水；原流水不能删除覆盖。冲正不恢复场次报名名额，也不能把同一笔奖励反复发放。

## 内测报障

记录操作场次、时间、步骤、提示信息和 traceId（如有）。只分享必要信息，不把真实名单、电话、OpenID、证件或密钥发到公开 GitHub issue。未确认的规则记入 [待决策清单](15-decisions.md)，不要对车友承诺示例分值。
