# 腾讯云环境、数据库和后台部署

## 何时开资源

页面和状态机模拟阶段不必先付费。要验证真实身份、多人报名、数据库和函数时就需要测试环境；不是等公开发布才需要后端。先查账号免费资格、额度、能力和期限，不能预设永久免费。正式运营前落实付费与续期，避免内测完成后资源到期。

本方案使用 CloudBase 原生云开发，不要求采购微搭低代码、独立 VPS、MySQL、域名、SSL 或支付商户。后续确有自建 HTTP 网站/后台才重新评估域名、备案和机器。

## 操作顺序与交付物

1. 公司管理员确认已有腾讯云账号、实名和小程序绑定情况；记账号归属和计费责任人，不记录密码。
2. 在当前 CloudBase/微信云开发官方入口检查能否开通。企业的微信认证条件按实际入口核对；本包建议管理员与开发并行办理微信认证。不要因独立云环境可创建就认定小程序已获微信云调用权限。
3. 检查已存在环境，确认地域、文档型数据库和相关能力。地域选择以当前平台支持为准；不因为俱乐部在北京就编造一个“北京 CloudBase 文档库地域”。
4. 开测试环境，名称例如 oradv-test；记录实际 EnvId、地域、套餐、到期、权限身份。名字不是 EnvId，不能只凭相似名称部署。
5. 授权开发者环境/项目相关操作，分别验证函数、数据库、索引/规则、存储和日志；无权限先补最少所需，不把广泛全产品管理策略描述为仅允许单函数部署。
6. Linux 设备码登录后列环境，与控制台核对 EnvId；填入本地配置。
7. 应用并核验版本化集合／索引／权限规则，再部署函数；主理人本人真实登录建立档案后，由可信部署者完成一次性员工初始化。每次命令明确目标EnvId。
8. 前端构建时写入测试 EnvId，验证微信真实身份和一条报名→核验→发分链路。记录真实结果。
9. 上线前明确正式环境配置。现有环境在套餐、额度和验收满足后可继续正式使用，无需仅因上线重复购买；若将测试环境转为正式，先停止其测试用途，再调整配置，不能把同一EnvId同时配置为test和production。后续建议另设隔离测试环境，不复制虚构成员、角色与积分。
10. 配好账单/配额/错误提醒、备份与恢复记录，再构建连正式环境的审核包。

## CLI 命令的使用方式

实施时先核对已安装版本帮助：

    tcb --version
    tcb env list
    tcb fn deploy --help

当前文档中的函数部署格式示例：

    tcb fn deploy <函数名> -e <真实EnvId>

尖括号是需要替换的占位说明，不能直接复制执行。函数目录、安装依赖、运行时与 timeout/memory 等按当前版本配置并写入版本化部署清单。若使用 cloudbaserc.json / 声明式部署，先查看当前 CLI 的 validate/dry-run 支持，不能把某版本语法当成永远兼容。

数据库集合、索引、规则、存储权限、定时任务和环境变量不是“上传函数”自动完成的。AI 必须交付迁移/预检/对账工具，所有生产执行显式指向正式环境。

## 管理后台的实际形态

首期开发同一小程序内的“员工工作台”。主理人用微信进入，在业务界面发活动、核验、查积分；不必自己操作 Linux 或腾讯云数据库。腾讯公众平台负责小程序账号与版本，腾讯云控制台负责基础资源，都不能替代产品工作台。

第一次 owner 由有权部署者通过受限初始化流程设置；真实成员先登录获得内部ID，再绑定员工。初始化结束关闭一次性入口，不能留下任何人可调用的 bootstrapAdmin。

## 成本控制

先给图片设置压缩和大小限制，列表分页、日志脱敏与保留期限。按套餐是否支持设置预算告警、额度告警及可控费用上限；告警不保证实时，也不一定自动停止计费。测试/正式两个环境可能分别收费，核对订单。

## 本项目为何先用云开发

“云开发”是后端产品名称，提供数据库、存储、身份和计算能力；开发者或 AI 负责代码，并不会替代这些线上资源。微信云托管适合托管自建容器后端，也可配合其他数据服务，并非购买后自动具备本项目完整后端。

首版沿用原生小程序＋云函数＋文档数据库，以减少内测接入工作。当前不另购云托管、VPS 或 MySQL；先核对小程序关联测试环境的套餐、到期和权限。参见 [CloudBase 产品文档](https://docs.cloudbase.net/)、[云托管介绍](https://docs.cloudbase.net/run/introduction) 及 [测试云开通步骤](18-beta.md)。此为本项目技术选择，不表示其他方案不能实现。

## 当前可部署代码与初始化计划

`npm run build` 同时生成云函数 `cloudfunctions/oradv/index.js` 和 `lib/index.js`。在函数目录执行 `npm ci --ignore-scripts` 安装锁定依赖；函数默认入口是 `index.main`。设置 `ORADV_ENV_ID` 为真实测试 EnvId、`ORADV_APP_ID` 为本小程序 AppID，实际运行环境必须匹配。运行时选用当前平台支持的 Node.js 18 或以上版本，并实测锁定 SDK 的兼容性；本地构建不代表已部署。

```sh
node scripts/cloud-plan.cjs --env test --config config/local.json
node scripts/cloud-plan.cjs --env test --config config/local.json --check
```

第一条输出离线计划；第二条在本地配置不完整时返回失败。结构计划位于 `config/database-plan.v2.json`，所有集合均拒绝客户端直读写。计划工具不会执行数据库迁移：实际集合、索引、安全规则须由部署者按当前控制台应用并核验，记录版本和结果，不能把计划当作已初始化。

真实微信用户首次同意后建立内部会员，再由可信部署者初始化首位 owner。单独的 `work/cloud-bootstrap-owner.cjs` 默认为计划，不是任何用户可调用的云函数。其 `--execute` 需要匹配本地测试环境以及受授权的云部署身份；未取得实际身份前不执行。查看 `node work/cloud-bootstrap-owner.cjs --help`，不要将云凭据发到聊天或 GitHub。

编号版初始化会同时将经核实的首位主理人成员设为0号，并写入角色、占号、审计和关闭标记。CLI的`--member-id`仍是内部成员ID，应由受信部署者在后台核对真实主理人档案后使用，不能把界面数字编号或昵称直接作为授权依据。若该档案已领过正号，旧号继续保留占用；其他已分配编号不重排。本轮未执行真实初始化或旧库补号。

## 0.2a增量结构

当前计划为v2，保留v1作追溯。新增 `activity_briefings` 与 `public_recommendations`，以及成员目录、技能和本人核验时间线所需索引；两类新增集合仍禁止客户端直接读写。现有成员缺少业务身份字段时按普通成员处理，不自动升为创始成员；现有已确认报名与积分流水不自动重写。

先由可信部署者初始化owner，再在产品内配置经确认的公开联系、成员身份和行前安排。本机演示联系、创始身份、活动与积分不得导入真实环境。离线预检在没有实际测试EnvId时返回失败，这是预期缺项；本轮未因此创建资源或代购。

## 微信登录与个人头像接入

本项目使用 `wx.cloud.callFunction` 调用 `oradv`，云函数从可信微信上下文取得AppID/OpenID，再建立或恢复本人档案。无需为此另建账号密码、在前端放AppSecret或重复接 `code2Session`。登录标识、用户主动选择的昵称／头像、主理人核定的业务身份分别处理。

部署前将测试EnvId填入本地配置，应用数据库v2计划，核对函数环境变量并部署；再把 [云存储规则](../config/storage-rules.v1.json) 应用到测试环境，拒绝客户端直接读写。头像由鉴权后的云函数写入 `member-avatars/`，仅本人通过业务接口取得临时显示链接。规则文件只是离线计划，必须实际验证微信客户端直读／直写拒绝、云函数本人读写成功。

`oradv`只用于微信小程序原生调用，不添加HTTP、Web、定时或其他混合触发入口。[CloudBase实例复用说明](https://docs.cloudbase.net/cloud-function/instance)指出，混合来源调用时 `getWXContext()` 可能读到上次调用残留的身份；如以后新增独立网站，另建并验证对应身份入口。

切换到云构建后，用两个独立微信账号验收：首次同意登录→默认零积分／普通成员→修改昵称→选择并保存头像→关闭重开恢复→第二个账号看不到第一人的私有头像。检查昵称未改变成员核定、员工授权或历史积分。用户现已提供测试EnvId，本地已核对环境绑定及上海地域；管理员CLI授权和数据库结构已完成，云存储规则因免费套餐限制未能应用，函数仍未部署，当前不能记为真实微信登录或云存储通过。

## 当前接入与费用分工（2026-10-16）

用户已自行申请免费环境，实际EnvId只写入本地忽略配置。微信环境列表返回NORMAL、文档数据库RUNNING，函数／数据库／存储地域均为ap-shanghai；套餐标签显示个人版，不据此推断已付款、试用期限或全部配额。免费权益及到期以管理员实际控制台为准。

新增只读检查工具，默认不加载SDK、不读取私钥、不联网：

```sh
node scripts/wechat-cloud-inspect.cjs inspect --env test --config config/local.json
# 实际查询需显式核对目标，尖括号为占位内容：
node scripts/wechat-cloud-inspect.cjs inspect --env test --config config/local.json --execute --app-id <实际AppID> --env-id <实际测试EnvId>
```

工具使用固定miniprogram-ci 2.1.31的私有环境查询适配器，并校验模块哈希；这不是公开稳定的管理API。只查询关联环境元数据，其余集合、索引、规则、函数、业务及计费均记NOT_RUN，报告保存在忽略的work/cloud-reports。实际上传通道已拒绝数据库等管理查询，不通过更换请求方式绕过；现已通过官方CloudBase CLI获得管理员设备授权，后续管理使用公共SDK，不继续扩展私有适配器。

用户明确不处理资金。管理员使用与小程序绑定的云账号负责套餐购买、升级、续费、按量计费和账单；开发者只处理开发与技术部署。如管理员看不到现有环境，先按[官方账号说明](https://docs.cloudbase.net/faq/account)核对登录与绑定，不直接新购替代环境。开发和云资源权限、产品内owner权限分别核验。

### 公共SDK首次数据库初始化

`scripts/cloud-setup.cjs`使用固定`@cloudbase/toolbox@0.9.1`和`@cloudbase/manager-node@5.9.1`，安装到忽略的`work/cloud-tools`。复用官方设备授权，临时凭据仅在内存中使用，不要求把永久密钥发给开发者。默认只打印离线计划：

```sh
node scripts/cloud-setup.cjs apply --env test --config config/local.json
# 实际执行另加 --execute --app-id <实际AppID> --env-id <实际测试EnvId>
```

仅用于首次空专用环境：已有业务记录、无关集合／函数、已部署oradv或索引冲突均在写入前拒绝。它创建集合、写拒绝客户端规则、创建非唯一索引并精确回读；实际count查询不信任列表缓存计数。存储规则影响整个环境，因此禁止用于混用环境。工具不导入业务文档、不部署函数、不删除资源或更改计费。

本次18个集合、24个索引及数据库规则已远端读回，所有业务集合为0条。到存储步骤时平台返回`OperationDenied.FreePackageDenied`；当前PRIVATE不是所需的拒绝客户端规则，不作放宽替代。管理员升级现有环境后可在尚无业务数据／函数时重跑；存储验证通过后才继续函数部署和云版交付。不得宣称索引定义读回就是查询或手机验收。
