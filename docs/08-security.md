# 身份、权限与隐私

## 三种后台身份不能混用

1. 微信公众平台：管理员、项目开发者/运营者、体验成员。决定谁开发、上传、管理版本或体验。
2. 腾讯云：公司账号及被授权身份，决定谁操作环境、函数、数据库、存储、日志和账单。
3. 产品内员工：owner/operator/leader/checkin，决定谁发布活动、审核、核验和结算。

三者不会自动互相授予。被加成开发者不能自动读取所有云资源；有云权限不能自动作为产品领队或主理人；体验者不能获得员工接口权限。首次owner必须由可信部署者绑定经核实的真实成员，随后在产品内授权；不能因开通环境、上传代码或成为首位注册者直接授权。

## 服务端身份与角色

微信原生云函数入口使用当前 SDK 提供的可信微信上下文取得 OpenID/AppID；根据应用建立 users 与 membership。不要接受 payload.openid、payload.role 或用户自填 memberId 作为当前身份。

如改为 HTTP 或独立 CloudBase 环境认证，必须另行验证 token/ticket、签发者、受众、有效期和访问范围，不能照搬前端伪造身份。不要为了登录方便给所有云函数开放匿名员工操作。

当前oradv仅接受微信小程序原生调用，不挂HTTP/Web/定时等混合入口；`getWXContext()`依赖运行时上下文，混合调用存在实例残留风险，不能只校验AppID/EnvId就当作已消除。[官方说明](https://docs.cloudbase.net/cloud-function/instance)。

| 查必要活动名单 | 否 | 授权场次 | 授权场次 | 本俱乐部 | 本俱乐部 |
| 出发/结束核验 | 否 | 授权阶段/场次 | 授权场次 | 本俱乐部 | 本俱乐部 |

这是当前代码权限边界；真机与真实云验收另记。所有入口校验clubId、活动范围、角色有效期和资源归属。撤销角色后实际失效，不能仅删除菜单。公开的“主理人／领队”等职责称谓只是内容，不能生成staff_roles或qualifications。

## 客户端与数据库

v3的27个集合均拒绝客户端直接读写，包括公开投影与栏目集合。2026-10-16已读回27个数据库`CUSTOM`禁止规则与存储禁止规则；这只证明当次结构配置，不能代替客户端越权、真实身份和业务事务验收。云函数拥有服务端访问能力，仍需每次鉴权和字段白名单，不能“把整条记录发给前端但不显示”。

图片上传限制用途、大小、类型和所属人；资格材料不能使用永久公开 URL。活动公开图与私密材料存储路径和权限分开。日志只保留必要技术字段和脱敏对象ID，严禁整份名单/证件/请求体打印。

## 隐私字段清单

| 信息 | 用途与时机 | 限制 |
|---|---|---|
| 微信内部标识 | 建立和恢复本人账户 | 不展示、不用于公开榜单 |
| 昵称 | 个人界面及自愿榜单 | 榜单与推荐分别选择，可退出 |
| 可选头像 | 本人资料页主动选择后保存 | 不默认公开，不进入员工目录、推荐或积分榜 |
| 必要联系电话 | 申请及现场联络，按必要性收集 | 仅有权工作人员，不公开 |
| 资格结果/有效期 | 活动准入与安全核验 | 优先存结论，不默认收原件照片 |
| 签到和完成记录 | 名单清点、积分和纠错 | 不默认持续定位，不公开轨迹 |
| 骑手资料、护具、车辆及轮胎照片 | 本人准备与owner人工核对 | 提交用途单独确认；草稿与审核快照分开，拒收身份证及医疗原件 |
| 可选紧急联系人 | 骑手自主填写并按用途提交 | 非登录或报名统一必填项，不公开 |
| 商务／兑换咨询联系方式 | 本人明确同意后交组织方处理 | 仅本人和owner，不形成支付、合同或自动扣分 |
| 评价与本场荣誉 | 完整参加者自愿投稿 | 内容、昵称及荣誉分别同意，审核后公开，可撤回 |

数据保存时长须结合服务、争议和法律要求确认，未决字段留空；禁止承诺“永远保存”或编造法定年限。注销流程需停止登录与公开榜单，对必要留存部分说明理由、期限和访问限制，按最终规则删除/匿名化。备份到期也要有处理机制。

## 上线隐私步骤

列清实际接口与 SDK → 填公众平台用户隐私保护指引 → 前端按实际能力触发说明与必要同意 → 拒绝处理 → 撤回/注销入口 → 真机验证。不要声明未用定位却调用定位，不要同意前采集手机号。

分清产品用户协议、隐私同意、线下服务约定、风险告知。线上“我已阅读”不能替代真实安全措施，也不能用免责条款消除依法应承担的责任。

## 0.2a的成员身份与受限资料

memberKind与staff_roles、qualifications分别核对。主理人认定身份需revision与依据，前端字段或成员编号不能作为授权依据。数字编号仅供通过既有可信渠道查找同名成员；不在公开推荐里返回内部成员ID、员工角色或核验材料。

俱乐部推荐与积分榜分别征求同意。未同意积分公开时，推荐响应不含成长分和完成次数；退出或注销后依据权威记录停止公开读取。集合细节放activity_briefings，不出现在公开活动投影；待确认、候补、取消和无关员工读取均拒绝。

新增管理页面仍完全依赖服务端权限，不以隐藏菜单保护。授权撤销／过期、旧无范围现场角色、本人主理人到期锁死等均有失败测试；未把本地模拟证明当成真实数据库规则证明。

成员编号0仅由受信初始化绑定主理人，不能通过客户端昵称、注册参数或资料修改认领。普通注册者从1领号；目录与名单数字精确查询仍先检查员工权限。序列／占号文档在clubs私有控制记录中，公共联系接口只读写固定俱乐部文档，不包含这些控制资料。已用号不回收，新增owner不自动占0；号码本身不授予任何角色。

## 个人头像

使用微信原生`chooseAvatar`与昵称填写能力；拒绝或不提供头像仍可登录和报名。头像仅通过本人的`profile.avatar.save`保存，不接受客户端成员ID、文件ID、远程URL或路径。云函数独立校验JPEG/PNG格式、64KiB字节与尺寸，并执行单独限频。资料图片使用独立媒体接口；各RPC请求上限见[接口合同说明](07-api.md#请求上限与临时链接)。

云存储维持客户端禁止直读、直写。每次上传使用唯一新路径，事务再次核对当前账号及revision后关联，失败只清理本次未绑定文件。成功后的旧图清理失败不撤销已经保存的资料，技术日志只含操作和错误码，不记录图片内容、文件标识或临时URL。数据库不保存base64或短期URL。

本人读取头像时按当前有效账号签发显示链接，公开接口不返回头像；注销后停止后续签发。已取得的临时链接存在有效期，不能承诺已发链接即时撤销。删除、失败清理和存储规则均需在实际测试云验证。

## v3资料、学习与媒体

资料提交将护具及每辆车的照片绑定到对应快照，owner只能审核当前待审提交，不能读取他人未提交的草稿。修改后需要重新提交；旧快照和已绑定素材不随新编辑覆盖。技能提交同样保留逐版归档；人工复核、知识练习成绩、活动资格与积分是不同事实，不能自动互相替代。

图片由鉴权云函数接收受限字节、独立校验并写入唯一新文件，素材编号由服务端生成，不接收任意fileID。`dossier`和`skill`保持私有；`club_public`仅owner明确确认公开使用权后创建，使用不带内部身份的随机路径，禁止挪用私密材料。公开图片也只能在其已发布回顾内解析链接。

当前云端短片上传返回`MEDIA_VIDEO_UNAVAILABLE`，不会把本机选择、客户端声明的大小或进度条当成已上传。8MiB／60秒短片仅在本机演示验证和保存；云草稿保留在设备，不能宣称已进入云审核。未经验证的上传元数据不能证明最大文件大小受限，因此不向客户端发放宽泛上传授权。

## 公开内容与撤回

栏目草稿只给owner；发布需明确确认内容已核实并获得公开所需授权。往期回顾仅限已结算活动；评价先核对完整参加且未冲正，再取得内容与昵称同意，荣誉另行选择。owner不能替成员同意，也不能更改投稿人的星级和正文。

每次公开读取重新核验作者当前状态、评价审核、三类同意及参加记录。撤回、账号停用／注销或完成记录冲正，会停止后续评价及荣誉展示。公开投影不含私人联系方式、头像、成员编号、内部成员ID或素材fileID。实际图片读取失败不计作已展示照片；影片必须为经核实的公开HTTPS MP4来源，原生播放失败明确提示，不模拟成功。

私有临时链接按300秒请求签发，实际到期以存储返回结果为准；撤回控制后续公开读取和签发，不能保证已经发出的链接或用户保存副本即时消失。日志只记录必要动作／错误码，不输出图片、短期URL、完整资料、咨询联系信息或请求正文。

## 本机身份、环境与未知结果

原生模块共用同一API和身份状态。页面恢复前台、写入前以及确认弹窗后，重新检查当前身份；身份变化清空私人草稿、图片引用与管理记录，相同身份保留未保存编辑。服务端仍从可信上下文鉴权，页面检查不替代服务端权限。

云媒体草稿按AppID、EnvId和成员隔离；咨询缓存按mode、AppID、EnvId、成员及栏目完整隔离。旧版未绑定环境的云草稿保留，不自动归属、上传或删除。咨询遇到未知提交结果时锁定正文，保存原submissionId与摘要；同一环境按原内容重试，不在新环境复用未知提交编号。

真实云环境不得导入演示成员、角色、题库、照片或积分。本机恢复过程只补缺少的演示内容，先保存校验后的快照，保留原档案与未识别字段；失败不得静默重置。开发者和owner均不得把本机演示通过等同于真实微信或生产数据验收。

## 原生调用事件与后台版本权限修复（0.3.0-test.2）

微信原生callFunction会在顶层自动附加userInfo；本项目2026-10-16真实手机日志还确认附加tcbContext。入口仅兼容并移除这两项平台元数据，再将五字段业务请求交给领域服务；原始事件仍计入大小上限，其他未知顶层字段和payload字段校验不放宽。身份仍仅来自getWXContext，不使用event.userInfo授权。见[CloudBase官方调用说明](https://docs.cloudbase.net/cloud-function/how-use)。

微信平台“开发者权限”用于开发／调试，“登录”用于本人进入后台，“开发管理”用于提交审核、发布、回退等版本操作。具备相应权限的开发负责人可管理体验版本和体验成员，不应把全部版本操作写成只能管理员执行；权限不足时由管理员在成员管理补充授权。云资源购买／账单和产品内owner仍分别管理。见[微信官方协同发布说明](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)。

实际tcbContext字段已通过多条本人页面／公开联系请求的受限日志确认，不是猜测扩展白名单。无论该对象包含什么uid、角色、AppID或环境字段，都不作为业务鉴权或环境选择依据；缺失可信SDK上下文仍在数据库访问前拒绝。
