# 积分、榜单和年度奖励

## 两类积分

成长积分 growthPoints：累计合格活动获得，作为报名门槛参考；报名不扣分，年末不归零。年度积分 annualPoints：按活动实际完成日期所属的北京时间年度汇总，用于该年度线下奖励。正常活动可同时形成两类积分增量。

参加次数 completedCount 只统计有效 completed，单一活动最多一次；候补、报名、签到、未到不计。没有完整核验时不能为了“好看”补完成。

## 建议初始规则，尚待确认

真实新用户从零开始；至少一类入门活动成长门槛为零。高难门槛 10000 来自用户举例，不是所有活动固定数值。活动具体奖励、技能要求、老会员历史迁移、退出积分、取消惩罚及年度奖励均须确认。

contracts/points-policy.json 为 proposed。fixture 只演示门槛，不表示真实报价、路线或主理人承诺。旧浏览器 demo 的 4200、10600 不得作为注册赠分。

## 流水与一致性

每笔积分流水包含 clubId、memberId、activityId、awardType、growthDelta、annualDelta、year、effectiveAt、ruleVersion、来源与操作人、原因、幂等业务键。可再记录 relatedEntryId 关联冲正。

正常完成业务键固定为 club/activity/member/completion；服务端事务在同一组提交中写：固定 ID 流水、汇总增量、报名 completed/settlementId。若流水已存在直接返回原结果。客户端 requestId 只辅助请求幂等，不能代替业务唯一性。

数据库事务不容纳整场时，按参加者逐个执行，结算任务记录总数/成功/失败/游标；最终对账完成再将活动标 settled。不要先把整场标完成再后台无追踪发分。

## 更正与冲正

禁止修改/删除原流水。带原因的新流水引用原记录：例如撤销完成 +100/+100，写 -100/-100 并同步撤销有效完成次数。对同一原记录不能重复全额冲正；再次确认需新版本与明确业务键。校验当前统计与历史，不简单将负数截成零来掩盖错误。

老会员历史迁移用单独 migration 流水，留来源与审核人；历史参加次数必须有可信依据，无依据不编造。原始申请和成绩不是可以随意改分的入口。

## 年度归属

活动真实完成时间 effectiveAt 计算 Asia/Shanghai 年度。12月31日结束、1月2日结算仍归前一年；跨年活动按最终完成日的统一规则，需在发布前说明。禁止按服务器 UTC 年份或结算执行时间分年。

1月1日不批量删除积分/流水。member_stats 用 memberId+year 保留年度分；成长汇总独立。年度榜单冻结为 snapshotVersion，记录截止、来源、规则与申诉期；冻结后更正保留旧快照与新版本，由运营决定奖励调整并留痕。

## 榜单和奖励

公开榜单先 opt-in，展示获准昵称/可选头像、成长/年度分、完成次数、本人名次；不展示 OpenID、电话、资格材料和线路。昵称内容做适用的内容安全处理。积分相同建议并列，同名按稳定内部排序分页，不渲染成比赛速度排名。

个人退出公开榜单，失效物化数据与缓存，不能只关个人页按钮。年度奖励内部名单允许完整运营数据的最小范围访问，公开展示另征同意。奖励清单和发放状态是线下奖品管理，不做积分购买、交易、提现或在线兑换商城。
