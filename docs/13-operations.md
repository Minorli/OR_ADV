# 发布、备份、恢复和日常运营

## 发布清单

冻结候选提交和 lockfile → 本地关键测试 → 测试云验证 → 真实手机与运营验收 → 记录正式数据迁移计划/备份 → 部署兼容后端 → 检查集合/索引/权限/任务 → 构建正式前端 → 预览核对真实环境 → 上传提审 → 通过后按授权发布 → 观察和对账。

保存 Git SHA、小程序版本、云函数版本、规则版本、迁移版本、AppID/EnvId、发布人和结果。不记录秘密。前端可能旧版本缓存，后端需兼容一段时间；不能假设微信一发布所有用户立刻更新。

## 备份

每日/每次重要迁移前检查数据库可恢复备份；备份范围包含核心集合、索引/规则定义、函数代码/配置版本、必要存储对象与引用关系、年度快照。存储备份与数据库回档不是一件事。密码/私钥另用安全方式保管，不打进业务备份。

具体快照、回档窗口和功能受套餐/数据库版本影响。按控制台实际能力记录恢复点和保留期限，不把某套餐“14天回档”当所有环境都有，也不把文档快照“7天”混为同一功能。缺少内置能力时另设计受限导出及存储成本。

备份含个人信息，访问控制和保留期限要覆盖它。不能把真实备份作为 AI 测试夹具提交 Git。恢复测试使用隔离环境并按需要脱敏。

## 恢复演练

建议上线前完整演练一次，之后按业务频率定期执行。参考目标 proposed：最多丢失一天业务（RPO≤24小时）、四小时恢复（RTO≤4小时），不是云服务承诺；实际能否达到由演练证据决定。

1. 选恢复点，记录包含的最后一笔有效报名/流水。
2. 在独立恢复环境恢复集合、索引、规则和所需文件，不覆盖正式库。
3. 跑报名人数、reservedSeats、有效完成次数、积分流水/汇总与年度快照对账。
4. 受限用户测试权限和主要流程；确认函数与数据版本兼容。
5. 记录耗时、丢失范围、差异、修复动作和是否达到目标。
6. 真实事故切换时明确新写入处理和回滚方案，防止双环境同时写造成分叉。

## 回退

小程序版本回退只处理前端，不能撤销数据库迁移、积分流水和已发送通知。函数回退也要保证旧版本兼容新数据。优先恢复服务、冻结有问题的写操作、对账后修复；不能直接恢复整库导致当天所有正确报名消失而没有业务补录计划。

## 监控与值守

监控云函数错误/超时、鉴权拒绝异常、报名写入失败、占位计数不一致、结算任务未完成、公开缓存失效、账单/额度/到期。日志使用 traceId，保留必要时间和错误类型；不记完整 phone/OpenID/材料。运营报障时提供 traceId 和时间，不要群发用户名单。

每场：核实人员/取消/出发结束/退出，结算预览后执行并对账。每月：核对费用、权限、恢复能力和依赖维护。每年：认证/主体/行业/保险等适用续期，年度积分冻结与奖励。手机号、负责人、主体或业务发生变化及时核对变更要求。

## 常见故障

| 现象 | 先查 | 避免 |
|---|---|---|
| Linux 登录无浏览器 | CLI 版本、设备码流程和授权身份 | 安装桌面微信或复制会话 |
| 上传 IP 不合法 | 真实出口、代理/NAT、白名单 | 关闭白名单掩盖配置问题 |
| 没看到云环境 | 账号归属、角色范围、实际 EnvId | 不断新建重名环境 |
| 手机看不到体验版 | 体验版本选择、体验成员、微信账号 | 把上传成功当已发布 |
| 活动有页面但报名失败 | 前端 EnvId、函数权限、集合/索引、真实状态 | 直接在前端发分或改名额 |
| 分数不对 | 流水业务键、规则版本、冲正/结算任务 | 直接修改用户余额 |
| 公众可见私密信息 | 关闭相关公开入口、查投影/存储权限、记录影响 | 仅从页面隐藏字段 |
