# OR ADV 项目续作规则

先读 README.md、HANDOFF.md、docs/02-requirements.md、docs/15-decisions.md，再检查已有代码，勿从头重复开发。

## 业务优先级

用户明确要求优先于本包；本包最新确认的需求优先于参考 HTML 和旧简版任务书。references 是页面参考，不是可直接部署的原生代码。真实业务有线下收费；小程序不展示价格、不收款、不记录缴退款。不为审核把真实训练写成免费普通聚会。

第一版单俱乐部，非铺装越野、技能训练、多日穿越，无比赛。食宿和交通由参加者自行安排。积分是准入参考，技能及安全核验必须独立。未确认的细节标为 proposed，不得写成主理人已决定。

## 工程约定

建议原生 TypeScript/WXML/WXSS、小程序云开发、云函数和文档数据库，同一小程序提供员工工作台。可因确切兼容性问题调整并记录理由，勿无理由引入多端框架、独立服务器、支付、社区或旅游系统。

实际源代码放 app/miniprogram、cloudfunctions、shared、tests。前端只保留公开配置，后端取得可信微信身份；所有员工命令服务端鉴权。成长积分、年度积分、名额和结算必须有事务、幂等和审计。

没有真实账号时完成本地工作并明确 mock；真正云部署、微信登录及手机验收必须有实际证据。不要臆造成功日志。工具脚本不是产品实现；不要把契约文件当成数据库已经建好。

## 账号与执行边界

不得输出、提交或嵌入 AppSecret、CI 私钥、云 token、验证码、真实名单。配置只读本地排除文件或正式密钥服务。不复制管理员微信会话，不让 AI 长期接管个人微信。

开发测试、代码修改、可逆修复正常推进。生产发布、购买与付费、正式数据修改按已有授权范围操作；缺少权限或本人核验时，写清需要哪位人员完成哪一步。不要对已经明确授权的正常开发反复索要确认。

先核对云账号和已有资源再创建；默认测试环境。部署命令必须明确 EnvId，微信上传必须核对 AppID、前端 EnvId、构建版本和目标环境。不通过关闭白名单解决 IP 配置错误。

## 持续交付

按 docs/16-delivery.md 分阶段完成；每阶段执行必要测试，维护 HANDOFF.md、PROJECT_STATUS.json、决策记录和发布记录。只记录不敏感信息。遇到平台受阻仍继续独立的实现与测试。

工具版本、腾讯类目/权限/价格会变化。接入时查官方文档和实际后台，记录日期，不照搬旧版命令或买到个人名下。出现差异先修正规格和记录，不隐藏平台要求。
