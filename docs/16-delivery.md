# 开发里程碑与交付出口

工期取决于开发者、AI工具和账号配合，以下按成果排顺序，不承诺无依据的完成天数。

| 阶段 | 实际工作 | 必须交付与验证 | 外部依赖 |
|---|---|---|---|
| M0 环境与骨架 | 检查 Linux，建立私有仓库、原生TS项目、配置分离、领域类型 | 可重建目录、命令、类型/构建检查，当前状态 | 开始时不依赖云 |
| M1 模拟业务闭环 | 活动列表/详情/报名/我的、员工审核和状态、积分只读 | 可体验模拟版；状态和并发领域测试；清楚标 mock | 不依赖正式账号 |
| M2 真实身份权限 | 测试云、集合规则索引、可信微信身份、员工初始化 | 真微信新用户、角色鉴权与越权失败证据 | AppID、成员权限、测试环境 |
| M3 报名与现场 | 事务名额、候补、取消、核验、异常状态 | 最后名额竞争/重试测试；手机完整参加链路 | 已确认规则与真实试用 |
| M4 积分年度榜单 | 幂等结算/冲正/对账、年度快照、自愿公开 | 一人一场只一次；跨年、退出榜单、结算失败重试 | 积分和奖励规则 |
| M5 正式准备 | 隐私、内容、类目资质、备案、正式云、备份恢复 | 真机验收、恢复记录、发布清单、可审核正式包 | 主理人材料、适用官方流程 |
| M6 发布与移交 | 提审、按真实驳回修复、发布、小范围运营 | 实际版本状态、活动人员和积分对账、员工说明 | 审核与发布授权 |

每阶段源代码提交、测试和运行说明都要能由另一位开发者复现。前端mock不能作为后端完成证据，CI上传不是公开发布证据。不能只做UI后声称“后端留给云平台自动处理”。

## 推荐首次真实链路

新微信用户零分建立身份 → 申请零门槛测试活动 → 运营审核和确认 → 限场领队出发/结束核验 → 运营完成结算 → 会员看到一次积分流水 → 主理人看同一名单和结果。再处理候补、复杂资格和批量年度奖励。

## 每次结束写清

已完成且已执行验证的内容；仅实现未运行的内容；仍模拟的内容；缺少权限/资料；下一条具体任务；需要主理人执行的一次性动作。更新 HANDOFF 和 PROJECT_STATUS，避免下次AI重写全部项目。
