# OR ADV · AI 开发启动任务书

当前进度：小程序账号已提交注册，正在等待注册信息／主体核验。尚未认定微信认证、类目、小程序备案、云开通或代码审核已完成。更新时间：2026-10-15。

本文件可与交互原型、上线操作手册一起交给 Linux 开发机上的 AI 编码工具。它是开发任务，不包含真实账号凭据，未替用户连接或配置 Linux 机器。

## 1. 第一版范围

- 运营主体拟为原始拉力（北京）运动服务有限责任公司，主体资料以最新有效执照核对。
- 一个俱乐部先用；数据包含 clubId，为未来扩展保留条件，不在第一版开放其他俱乐部入驻。
- 真实服务包括线下收费的非铺装摩托车越野、技能训练及多日穿越，不办比赛。
- 食宿交通由参加者自行预订并直接支付，公司不代订、不代收。
- 小程序只做招募、报名意向、资格核验、员工确认参加、签到、完成核验、积分与榜单。
- 不展示价格，不在线支付，不记录金额、缴费、退款、充值或会员收费状态。不把真实有偿活动宣传成免费。
- 员工在线下向申请者说明真实服务、费用、退改及风险，双方确认后在线上登记确认参加。
- 积分不购买、不充值、不提现。成长积分用于报名门槛，年度积分用于线下奖励；技能、资格和现场核验独立于积分。
- 无公众发帖、评论、私信、商城、旅游代订、比赛和会员储值。

## 2. 技术方案与设备分工

- 前端：微信原生小程序，TypeScript + WXML + WXSS。
- 后端：腾讯云开发 CloudBase 云函数，使用部署环境实际支持、仍受维护的 Node.js 运行时。
- 数据：CloudBase 文档型数据库；图片使用云存储。
- 管理：同一小程序中开发员工工作台，角色包括主理人、运营、领队、签到员。
- 环境：测试、正式分别使用独立 EnvId、数据库和配置。
- Linux 开发机：AI 编码、Git、依赖安装、检查和测试、云函数部署、小程序编译／预览／上传。
- Mac 或 Windows：建议保留一台可运行官方微信开发者工具的电脑，用于模拟器和真机调试；手机微信完成真实验收。
- 上线后的数据库和云函数运行在腾讯云；用户页面运行在微信。Linux 开发机关机不应影响正式业务。

不因本项目先采购 VPS、独立 MySQL、域名或支付服务；若更改技术方案，先说明具体需求、费用和维护责任。

5. 准备两场真实活动的内容模板、积分规则、隐私说明与用户规则草案，交主理人补充确认。
6. 输出仍缺的账号、资料、业务规则和平台权限清单；账户尚未开放的能力不伪装为联调通过。

## 4. 核验通过后的账号准备

由管理员在官方平台完成，AI 可以准备步骤和协助检查：

1. 确认小程序 AppID，添加开发者微信为项目成员。不要使用公众号 AppID。
2. 完善名称、介绍、头像与客服，按真实服务核对类目、行业条件和备案要求。
3. 启动小程序备案；按实际功能和账号提示判断是否办理微信认证，不将注册通过当作其余审核通过。
4. 核对公司腾讯云账号及小程序关联；创建测试环境，再在上线准备阶段落实正式环境与套餐。
5. 记录 EnvId、地域、套餐和到期责任人；以测试环境完成第一轮微信身份和数据库联调。
6. 准备体验成员，分清微信体验权限与项目自己实现的员工角色权限。

## 5. Linux 自动化接入

### 小程序代码上传

- 使用微信官方 npm 包 `miniprogram-ci`，生成预览码和上传代码。
- 由管理员在“管理 → 开发管理 → 开发设置 → 小程序代码上传”生成代码上传密钥。
- 将实际上传进程使用的公网出口 IP 加入白名单；私网地址不是公网出口。若通过代理上传，应按真实出口配置。
- 私钥放在机器受限目录或发布任务的 Secret 中，脚本只读取路径。不得写进源码、前端包、文档、日志或 AI 对话。
- 代码上传密钥、AppSecret、腾讯云 API 密钥／登录凭据用途不同，不能互换。
- `miniprogram-ci` 的预览／上传不等于完成备案、代码审核和公开发布。

### 云端部署

- 使用官方 `@cloudbase/cli`，由公司授权的身份登录，配置明确的目标 EnvId。
- 无图形界面的机器可按当前 CLI 文档使用设备码登录，在另一台设备浏览器完成授权；不要求 Linux 具有桌面浏览器。
- 开发过程默认使用测试环境。正式发布任务单独使用生产授权和配置。
- 需要覆盖 CloudBase 及其底层资源的权限时，逐项核对实际操作和策略范围；不要把含多产品完全控制权的预设策略误认为只允许部署一个函数。
- 数据库集合、索引、访问规则和初始角色也要有可重复的部署步骤，不能只上传函数。

### 微信后台管理

- 初期无需让 AI 持续登录并点击整个公众平台后台。优先让 CLI 完成可重复的开发和上传工作，管理员处理身份、备案、能力申请等平台流程。
- 微信另有 `miniprogram-mp-ci`，当前官方文档列出的能力是批量成员管理；调用成功后还需管理员微信确认才生效。它不是整个公众平台的通用管理接口。
- 如需浏览器协助查看状态、填资料，应使用已获授权的操作工具；本人扫码、验证码、协议、资质与费用由有权人员按官方流程处理。
- 第一版建议保留人工验收后再提审、发布。自动提审和发布是否可用，需另查该账号实际开放的官方能力，不能由上传权限推断。
- 俱乐部活动、名单和积分的日常管理使用自建工作台，不能用公众平台成员管理接口代替俱乐部成员／业务权限。

## 6. 必须满足的业务验收

- 微信身份由云函数可信上下文取得，不信任客户端提交的用户身份或员工角色。
- 敏感集合限制客户端直接访问；每个员工接口在服务端核对角色、活动与 clubId。
- 报名意向 → 资格审核／候补 → 待联系确认 → 确认参加 → 出发／结束核验 → 完成结算。
- 两人争最后一个名额只允许一人占位；重复点击不重复报名。
- 积分足够仍须满足资格要求；只报名或签到不发完成积分。
- 积分流水、汇总和结算状态保持一致；并发或重试不重复发分；更正追加冲正流水。
- 公开榜单仅展示自愿公开的必要字段，不能包含手机号、OpenID 或证件等信息；退出选择实际生效。
- 正式环境与测试数据隔离；上线前执行一次数据备份与恢复核对。
- 在真实微信、至少关键 iOS／Android 设备上完成验收，模拟界面和单元测试不能代替。

## 8. 建议的第一次可用版本

先打通一条完整链路：一个真实微信成员建立身份 → 申请一场活动 → 运营确认参加 → 领队出发和结束核验 → 完成后发一次积分。主理人在工作台看到同一份名单和结果。

这一条真实云端链路验收通过，再补齐候补、资格有效期、榜单、年度奖励和异常处理。正式开放前仍须完成所有适用前置条件和验收，不以功能试跑代替上线审核。
